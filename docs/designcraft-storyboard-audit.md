# DesignCraft storyboard integration audit

Read-only source audit. Magic pins `designcraft-engine` 0.17.0 at [4f3bb534](https://github.com/storytold/designcraft/tree/4f3bb5340eeee5f747f7ee2a6905d3c990831d22) (`Cargo.lock`); the installed `designcraft-cli` reports 0.18.0, so its registry is useful for discovery but does not establish pinned-version support. Pinned references: [control protocol](https://github.com/storytold/designcraft/blob/4f3bb5340eeee5f747f7ee2a6905d3c990831d22/docs/control-protocol.md), [MCP and render commands](https://github.com/storytold/designcraft/blob/4f3bb5340eeee5f747f7ee2a6905d3c990831d22/docs/mcp.md), and [engine command registry](https://github.com/storytold/designcraft/tree/4f3bb5340eeee5f747f7ee2a6905d3c990831d22/crates/engine/src/cmd). No live editor or production project was modified.

## Priorities

1. **Protect the document owner (confirmed competing-session risk).** [`Board::open` and `save`](../crates/engine/src/cmd/storyboard/mod.rs#L152) open a fresh in-process session and save to disk; [`storyboard.set`](../crates/engine/src/cmd/storyboard/mod.rs#L770) uses it even if DesignCraft has the same document open with unsaved edits. Native `document.inspect {}` reports the active `path` and `dirty` state ([pinned inspect source](https://github.com/storytold/designcraft/blob/4f3bb5340eeee5f747f7ee2a6905d3c990831d22/crates/engine/src/cmd/inspect.rs#L107)). Verify the exact canonical active document and either use its live session with explicit ownership/save semantics or fail closed; protect the separate-session save against intervening disk changes too. An inspection followed by a mutation is not atomic.

   **Endpoint matters:** [`storyboard.open`](../crates/engine/src/cmd/storyboard/mod.rs#L996) defaults to port **7979**, accepts a `control` override, and the [current UI](../apps/magic/ui/views/StoryboardView.tsx#L66) explicitly passes 7979. [`CraftHub`](../crates/engine/src/craft_hub/mod.rs#L59) defaults DesignCraft to **9877**, overridden by `DESIGNCRAFT_CONTROL_PORT`; storyboard's `Board` does not use CraftHub. A guard that checks only 9877 misses the editor Magic starts. Track the actual endpoint and verify identity; a connection on a port alone does not prove document ownership. The open path also reuses any listener on the chosen port and sends `file.open`, so inspect its identity and dirty-document behavior before relying on reuse. Native protocol `app.quit` bypasses the unsaved prompt; do not use it to close a document as a shortcut.

2. **Show real layout and link problems beside the fields (confirmed missing integration).** Pinned `story.get {"frame": id}` returns `text`, `overset` (UTF-8 byte offset or null), and `oversetChars` ([registry](https://github.com/storytold/designcraft/blob/4f3bb5340eeee5f747f7ee2a6905d3c990831d22/crates/engine/src/cmd/text.rs#L194)). `links.list {}` returns asset status `ok`, `modified`, `missing`, or `embedded`, with `uses: [{id,page,ppi}]` ([registry](https://github.com/storytold/designcraft/blob/4f3bb5340eeee5f747f7ee2a6905d3c990831d22/crates/engine/src/cmd/links.rs#L27)). Native `preflight.run {"minPpi":150}` returns issues with severity, kind, message and optional item/page. Magic already runs preflight and associates page issues in [`completion`](../crates/engine/src/cmd/storyboard/mod.rs#L520), but the [inspector](../apps/magic/ui/views/StoryboardView.tsx#L71) marks fields absent from `unfilled` with a check. Map native item IDs and page indexes to slots when present; retain document-level issues without fabricating an item. A field that is filled can still be overset or have a missing image.

3. **Keep placeholder completion distinct from requiredness (confirmed semantic limit).** [`template_defaults`](../crates/engine/src/cmd/storyboard/mod.rs#L478) and [`completion`](../crates/engine/src/cmd/storyboard/mod.rs#L520) treat unchanged bracketed template defaults as unfilled; neither that comparison nor DesignCraft preflight identifies whether a slot is required. Author explicit required/optional metadata for this template before assigning those statuses. The UI's [`groupFor`](../apps/magic/ui/views/StoryboardView.tsx#L12) groups labels by regex; those are presentation heuristics, not native DesignCraft semantic categories.

4. **Reuse the native batch renderer for the page rail (confirmed repeated work).** Each visible [navigation thumbnail](../apps/magic/ui/views/StoryboardView.tsx#L19) calls `storyboard.thumbnail`, which opens the document again. Magic's [`storyboard.export {"png_dir": "…", "scale": 0.16}`](../crates/engine/src/cmd/storyboard/mod.rs#L958) renders all pages in one opened session; the pinned CLI also supports `designcraft-cli run --in FILE --scale 0.16 --all-pages DIR`. The `storyboard.thumbnail {"out_dir": "…"}` variant renders **scene pages only**, so it is not a complete page-rail batch. Cache by a reliable saved-file stamp and invalidate on change; live DesignCraft revisions are session-local and pinned `document.inspect` does not expose a revision. The native `ui.render {"page": 0, "scale": 0.7}` renders a live page when that session is the verified owner.

5. **Preserve page/spread identity (conditional imported-document risk).** [`Board::pages`](../crates/engine/src/cmd/storyboard/mod.rs#L227) enumerates spreads while [`render_png`](../crates/engine/src/cmd/storyboard/mod.rs#L919) passes its index to a page renderer. The embedded template inspected in this audit is `facingPages: false`, with 1600×1000 single pages designed as two-leaf layouts; no mismatch was established for that template. A modified or imported facing-pages document can have a different page/spread mapping, so verify native page indexes explicitly before rendering it. Use the native renderer rather than recreating it.

6. **Reuse existing placement, fit and duplication; respect undo ownership.** [`set_text` / `set_image`](../crates/engine/src/cmd/storyboard/mod.rs#L201) already call native `story.get {"frame":id}`, `story.setText {"story":id,"text":"…"}`, `place.load {"path":"…"}`, `place.drop {"x":0,"y":0,"frame":id}`, and `object.fit {"mode":"fillProportionally","ids":[id]}`. The latter covers the frame and crops; `fitProportionally` retains the whole image and may leave empty space. [`storyboard.add_scene`](../crates/engine/src/cmd/storyboard/mod.rs#L822) already uses `layout.pages.duplicateSpread {"spread":n,"to":n}`. Native `edit.undo {}` belongs to the current DesignCraft session: the fresh-open/save model does not give Magic a unified persistent undo history. Do not offer native undo against a different session. `storyboard.script` can run native steps in one session; check partial-failure behavior before describing a batch as atomic.

7. **Do not replace useful typed inspection with a guessed schema.** [`Board::pages`](../crates/engine/src/cmd/storyboard/mod.rs#L227) combines `document.inspect {}` bounds with the loaded typed document's labelled items, text stories, linked graphics and parent information; it is not parsing serialized document JSON. `object.findByLabel {"label":"…"}` returns matching IDs, and `story.get` and `links.list` expose other parts of the native model. The inspected command contracts do not supply a complete semantic slot/group/requiredness schema, so retain the typed traversal where needed instead of inventing a renderer or inferring more from names. Preserve the existing accessible page and field controls while improving the data behind them.

The [CLI adapter](../apps/magic-cli/src/main.rs#L89) already forwards storyboard commands to these engine operations. Further work should address the confirmed ownership and validation gaps before adding unrelated editor capabilities.
